# NIC document matching V1

`VERIFIED` means an OCR-extracted NIC matched the existing encrypted profile NIC, or an authorized safety Admin approved a manual document match. It is not a government record lookup, proof of card authenticity, or face match.

The backend accepts JPEG/PNG up to 5 MB and re-encodes the image to strip metadata. Automatic checks use local Tesseract OCR with an English model and a confidence threshold; that image and OCR text are discarded. Unreadable or ambiguous results are retryable. The account's unsuccessful attempt count is server-side, with a 15-second minimum between attempts. After two unsuccessful checks, the user may send a new image for manual review. A clearly different extracted NIC receives a neutral mismatch result.

Manual-review images are stored in the private Cloudflare R2 `uniwork-identity` bucket under random keys. Only the Admin API can read an image. The browser receives it with no-store headers and revokes its temporary object URL on close. Admins can reveal the profile NIC only inside the review detail. Each decision is audited and updates the existing profile's verification state. Image deletion runs after commit; failures remain marked for an hourly retry. Pending reviews expire after `IDENTITY_REVIEW_RETENTION_DAYS` (default 30) and are marked expired before deletion. Configure an R2 lifecycle backup longer than this period, such as 45 days. Monitor `identity_reviews.deletion_pending` and R2 lifecycle activity.

Build/deployment order: apply Flyway V13 by deploying the backend first, with stable PII key, Clerk config, private R2 credentials, and Tesseract installed. Confirm backend health and migration status. Deploy web next. Rebuild and distribute the Android app because it adds `expo-image-picker`; an OTA JavaScript update alone does not add the native module to an older APK. Use synthetic NIC images and test Clerk accounts for manual verification. Do not upload real personal documents during automated tests.

Use `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET_NAME=uniwork-identity`, and optionally `R2_ENDPOINT` only on the backend. The R2 token needs object read/write/delete and bucket listing for the cleanup sweep. Keep the bucket private. Never place credentials in `NEXT_PUBLIC_` or `EXPO_PUBLIC_` variables. Local OCR requires the Tesseract executable and English language data on PATH, or `IDENTITY_TESSERACT_COMMAND` pointing to it. Missing OCR returns a temporary service error without consuming an attempt.

The profile verification card explains the purpose, image processing, optional temporary R2 storage, deletion, and matching limitation. This description is a product notice; obtain a privacy/legal review before publishing a legal privacy policy.
